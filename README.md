# نظام حجوزات إيمان آل موسى

نظام حجوزات سحابي بواجهتين: صفحة عامة تحجز منها العميلة، ولوحة تحكم خاصة
تصل إليها الطلبات وتؤكّدها.

## الملفات

| الملف | الغرض |
|---|---|
| `index.html` | صفحة العميلة: اختيار الخدمة، ثم اليوم والوقت، ثم البيانات. وصفحة متابعة الحجز عبر `?t=<token>` |
| `admin.html` | لوحة التحكم: الطلبات، الأجندة، المستحقات، أوقات العمل، الخدمات، الإعدادات |
| `assets/theme.css` | الهوية البصرية — الألوان مستخرجة من الصورة المرجعية |
| `assets/icons.js` | ٣٠ أيقونة SVG مرسومة خصيصًا لهذا النظام |
| `assets/db.js` | طبقة البيانات والتنسيق المشتركة بين الواجهتين |
| `assets/config.js` | رابط قاعدة البيانات ومفتاحها العام |
| `assets/fonts/` | الخطوط محليًا، ليعمل التطبيق بلا إنترنت |
| `sw.js` | يخزّن هيكل التطبيق ليفتح فورًا وبدون شبكة |
| `supabase/migrations/` | مخطط قاعدة البيانات |
| `supabase/tests/` | ٢٥ اختبارًا للمخطط |
| `dev/` | أدوات تطوير فقط، لا تُرفع للاستضافة |

## التشغيل

### ١. قاعدة البيانات

أنشئ مشروع Supabase، ثم طبّق المخطط:

من لوحة Supabase ← SQL Editor، الصق محتوى `supabase/apply_from_scratch.sql`
كاملًا واضغط Run. الملف يحذف كائنات النظام إن وُجدت ثم ينشئها، فيصلح
للقاعدة الفارغة وللمطبَّقة جزئيًا على السواء، ويمكن إعادة تشغيله بلا ضرر.

تحذير: حذفه يشمل الحجوزات. بعد أن يستقبل النظام حجوزات حقيقية، استخدم
ملفات `supabase/migrations/` بدلًا منه:

```bash
psql "$DATABASE_URL" -f supabase/migrations/0001_init.sql
```

### ٢. حساب الدخول

من لوحة Supabase ← Authentication ← Users ← Add user، أنشئ حساب البريد
وكلمة المرور الذي ستدخل به زوجتك.

ثم — وهذه خطوة لازمة — أضف الحساب إلى قائمة المصرّح لهم، وإلا فتح اللوحة
وهي فارغة تمامًا. من SQL Editor:

```sql
insert into public.admins (user_id, email)
select id, email from auth.users where email = 'البريد-الذي-أنشأته';
```

مجرد امتلاك حساب لا يمنح أي صلاحية. الصفحة العامة تحمل مفتاحًا عامًا، ولو
كانت الصلاحية معلّقة على "مسجَّل دخول" لاستطاع أي شخص ينشئ حسابًا أن يقرأ
كل بيانات العميلات. لذلك تُمنح الصلاحية من جدول `admins` وحده، ويفحصها
`is_admin()` في كل سياسة.

ويُستحسن مع ذلك إيقاف التسجيل الذاتي: Authentication ← Providers ← Email ←
**Enable email signups** = off.

لإضافة أو إزالة مسؤولة لاحقًا، أضف أو احذف صفّها من `public.admins`؛
لا يمكن تعديل هذا الجدول من داخل التطبيق عمدًا.

### ٣. الربط

في `assets/config.js` ضع رابط المشروع ومفتاحه العام (Project Settings ←
API). المفتاح العام مصمَّم ليظهر في المتصفح: صلاحياته محدودة بسياسات
الصفوف، وهي تسمح بقراءة قائمة الأسعار وأوقات العمل المنشورة فقط، ولا تسمح
بقراءة بيانات العميلات إطلاقًا.

### ٤. الاستضافة

الملفات ثابتة (static)، ترفعها كما هي على أي استضافة: GitHub Pages أو
Netlify أو Cloudflare Pages. يجب أن تكون على HTTPS ليعمل التثبيت على
الجوال وخدمة العمل بلا إنترنت.

بعد الرفع:
- شاركي رابط `index.html` مع العميلات.
- افتحي `admin.html` على جوالك ← "إضافة إلى الشاشة الرئيسية" ليصبح تطبيقًا.

## كيف تُحسب الأوقات المتاحة

زوجتك تضبط في **أوقات العمل** قواعد أسبوعية: لكل يوم فترة أو أكثر (مثال:
السبت–الخميس ٤ م – ١٠ م، والخميس إضافةً ٩ ص – ١ م). ويمكن تجاوز الجدول
ليوم بعينه: إجازة، أو ساعات مختلفة.

عند اختيار العميلة لخدماتها، يحسب النظام مدتها الكاملة، ثم يعرض فقط
الأوقات التي:

1. تقع كاملةً داخل إحدى فترات العمل،
2. ولا تتقاطع مع حجز قائم بعد إضافة وقت الانتقال على الطرفين،
3. وتحترم أقل مهلة للحجز وأبعد تاريخ مسموح.

الفحص يُعاد على الخادم لحظة الحفظ، فلا تستطيع صفحة قديمة حجز وقت مشغول.

## الاختبارات

```bash
supabase/tests/run.sh     # ٢٥ اختبارًا على نسخة Postgres محلية
node dev/shots.js         # لقطات للواجهتين مقابل بيانات وهمية
node dev/dark-check.js    # التأكد من عمل الوضع الليلي
```

## ملاحظات

- التواريخ والأوقات تُخزَّن كتاريخ وساعة حائط، لا كطابع زمني عالمي. العمل
  في مدينة واحدة، وهذا يجعل "٤ م يوم ١٢" صحيحة مهما كان إعداد الجهاز.
- الحجز الفردي والجماعي شكل واحد: كل حجز يملك سطرًا أو أكثر في
  `booking_items`. الإجمالي والمدة يُشتقّان من السطور، فلا يتناقض الملخص
  مع التفصيل.
- سطور الحجز تحفظ نسخة من اسم الخدمة وسعرها ومدتها وقت الحجز، فتعديل
  التسعيرة أو حذف خدمة لا يغيّر حجوزات سابقة.
- خذي نسخة احتياطية من **الإعدادات ← النسخ الاحتياطي** بين حين وآخر
  واحتفظي بها خارج الجهاز.
